Modbus fundamentals

Modbus describes the request and response. RS-485 or Ethernet carries that message. A gateway bridges those two worlds, but it does not magically increase serial bandwidth.

Build the mental model

In conventional Modbus RTU, one serial master initiates requests, and a addressed slave responds. The segment has no token passing or native discovery. Each individually addressed slave normally uses an address from 1–247; address 0 is reserved for broadcast commands that do not elicit a response.

From BACnet MS/TP: both may use RS-485 wiring, but MS/TP uses a token for bus access among masters. Modbus RTU generally relies on a single coordinated master. Identical cable does not imply identical protocol behavior.

What travels in a request?

RTU frameAddress · Function · Data · CRC

Serial framing and CRC validation; timing depends on baud and format.

TCP application frameMBAP · Function · Data

MBAP contains the Unit ID. No RTU CRC is carried inside the TCP application data unit.

Diagnose by layer

Ping succeeds: gateway IP is reachable. TCP 502 opens: a TCP service is reachable. Valid Modbus response: an endpoint processed the request. Only a valid end-to-end response or meaningful downstream evidence demonstrates the target RTU transaction actually worked.

Engineering trap: 247 usable addresses do not establish 247 electrically allowable devices, 247 gateway routes, or acceptable polling performance.
