Registers & addressing

A correct request requires the right slave/Unit ID, function code, starting address and quantity. A successful transaction can still yield a nonsensical engineering value if decoding is wrong.

FC03Holding registers

Read 16-bit holding-register values. Conventional display labels start with 4xxxx.

FC04Input registers

Read 16-bit input-register values. Conventional display labels start with 3xxxx.

Try the address translator

For the traditional five-digit 4xxxx display convention, the displayed holding register 40001 corresponds to transmitted starting offset 0. Some vendors and drivers use one-based fields instead: verify the actual manual.

Five checks before calling the data wrong

  1. Slave ID or gateway Unit ID and serial port route.
  2. Function code and register table (FC03 versus FC04).
  3. Starting offset convention and requested register quantity.
  4. Signedness, 16/32-bit width, and byte/word ordering.
  5. Scale, engineering units, and manufacturer model/firmware revision.
Example: a two-register 32-bit vibration reading needs not just the correct starting offset, but the documented word order and scaling. Modbus does not standardize how a particular manufacturer encodes that measurement.
