Course overview

Learn the distinction between Modbus RTU and Modbus TCP, how RS-485 wiring affects reliability, how register requests work, and how gateway routing and polling affect performance.

Training sequence: Learn → Apply the playbook → Calculate → Demonstrate understanding. The sections are independent, so experienced engineers can jump directly to a task.

01.1 · Modbus fundamentals

Modbus is a request/response protocol. A client (master in older terminology) requests data from a server (slave); on a conventional Modbus RTU segment, one serial master coordinates requests.

  • RTU: binary messages with an address, function, data and CRC over a serial link.
  • TCP: Modbus messages over Ethernet/TCP with an MBAP header, commonly port 502.
  • Gateway: translates/forwards requests between TCP and an RTU serial segment; a successful ping does not prove RTU health.
Compare to BACnet MS/TP: token passing allows multiple masters to arbitrate. Modbus RTU does not use token passing.

01.2 · RS-485 physical networks

RS-485 defines an electrical interface, not a Modbus-specific addressing scheme. Design a trunk with a documented physical order, suitable cable, controlled stubs, and termination at its electrical ends.

  • Verify device supply voltage and A/B wiring against both manufacturers.
  • Provide termination and biasing appropriate to the actual transceivers.
  • Check reference, isolation, shielding and common-mode constraints.
  • Do not confuse the 1–247 Modbus address range with the gateway's node limit or RS-485 electrical capacity.
A reading near 60 Ω across an isolated, de-energized bus can suggest two 120 Ω terminations in parallel, but it cannot prove correct termination placement.

01.3 · Registers and addressing

A valid Modbus request needs the correct slave ID, function code, starting offset and quantity. Many vendor tables use a 40001-style display convention while the transmitted request uses a zero-based offset.

  • FC03: read holding registers.
  • FC04: read input registers.
  • Check signedness, scaling and byte/word order for multi-register values.
A Modbus exception is a valid protocol response indicating a request problem or device/gateway condition; a timeout means no valid response arrived in time.

01.4 · TCP-to-RTU gateways

A gateway can accept TCP requests and serialize them onto one or more RTU ports. Multiple clients share finite serial time, and routing behavior depends on the gateway model and configuration.

  • Document gateway IP, TCP port, Unit ID mapping and serial port.
  • Confirm connection limits, request queues and timeout ownership.
  • Do not assume duplicate slave IDs on separate ports can be reached through one IP/port without explicit routing support.
Commissioning sequence: verify Ethernet → TCP service → a known-good Modbus request → all devices → full polling load.

03.1 · Polling utilization

A healthy FC03/FC04 request has an 8-byte request and a response of 5 + 2R bytes. Estimate wire time, device processing, and turnaround per request; then divide total scan time by the target interval.

Utilization is a screening estimate. It does not prove gateway throughput or resilience to failures.
